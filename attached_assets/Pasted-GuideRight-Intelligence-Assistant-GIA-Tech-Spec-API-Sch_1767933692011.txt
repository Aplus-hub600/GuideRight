GuideRight Intelligence Assistant (GIA) — Tech Spec (API + Schemas + Guardrails)

This is a mission-oriented, evidence-grounded assistant that produces structured outputs tied to AOI + timeframe + artifacts + intelligence graph, with degraded deterministic mode when AI is unavailable.

1) System Contract
1.1 Core principle

No claim is “Supported” unless it references stored evidence (artifact IDs + snippet IDs, or graph node IDs).

1.2 Required context inputs

AOI: geometry + label (or “No AOI selected”)

Time window: time_from, time_to

Evidence scope: selected artifacts OR filtered artifacts

Graph scope: program graph + node relationships

1.3 Output style

The Assistant does not default to free-form chat. It outputs a mode with a JSON payload the UI renders.

3) Context Retrieval “Tool” Endpoints (internal, bounded)

These are what the assistant is allowed to query:

GET /context/aoi/current

GET /programs/{id}/graph?depth=1|2&include=...

GET /artifacts?time_from=...&time_to=...&tags=...&types=...&sensitivity_max=...

GET /artifacts/{id}/preview?max_chars=3000 (returns excerpt + snippet IDs)

GET /pmesii/latest?aoi_id=... (or by label)

GET /risks?program_id=... (or AOI tag)

GET /timeline?time_from=...&time_to=...&aoi=...

GET /system/status (quota/AI availability)

Hard bounds

limit artifacts: e.g., 50 per run

limit preview size: e.g., 3k chars each

limit graph nodes: via max_nodes

4) Output Modes + JSON Schemas

All modes share a common envelope:

4.1 Common response envelope (ModeResult)
{
  "schema_version": "1.0",
  "mode": "PMESII | RISK_BRIEF | SITREP | MISSION_SUPPORT | GRAPH_QUERY | ARTIFACT_SUMMARY | DEGRADED",
  "title": "string",
  "time_window": { "from": "ISO", "to": "ISO" },
  "confidence": { "level": "Low|Med|High", "score": 0.0, "basis": [] },
  "claims": [],
  "citations": [],
  "actions": [],
  "audit": { "tools_used": [], "policy_flags": [] }
}

4.2 Claim object (non-negotiable)
{
  "id": "clm_001",
  "text": "string",
  "tag": "SUPPORTED | ASSUMPTION | UNKNOWN",
  "confidence": { "level": "Low|Med|High", "score": 0.0, "basis": [] },
  "evidence": [
    {
      "artifact_id": "uuid",
      "snippet_id": "snip_11",
      "reliability": "A|B|C|D|E",
      "timestamp": "ISO"
    }
  ],
  "related_nodes": ["node:dependency:...","node:risk:..."]
}

Confidence scoring rule (deterministic)

Start at 0.20

+0.20 per independent evidence item (cap +0.60)

+0.10 if evidence reliability A/B

-0.20 if evidence is old vs time window (your definition)

Map final score:

<0.45 → Low

0.45–0.74 → Med

>=0.75 → High

If tag=SUPPORTED and evidence=[] → policy violation → must downgrade to ASSUMPTION or UNKNOWN.

5) Prompt + Guardrails Design (no hallucinations)
5.1 Two-stage execution (required)

Plan stage (internal): decide which tools to call and what evidence is needed

Synthesize stage: produce JSON only and validate it

5.2 Tool-calling policy (hard)

If user requests analysis but there are no artifacts and no stored intel:

output must be UNKNOWN and request uploads or specify missing feed

If AOI is missing for AOI-dependent questions:

ask user to select AOI (or produce “No AOI selected” warning)

5.3 Output validator (server-side)

Before returning final:

Parse JSON

For each claim:

If tag=SUPPORTED and evidence empty → fail validation → auto-downgrade tag or reject

Ensure citations refer to existing artifact/snippet IDs

Enforce max lengths (prevents prompt injection dumping)

6) Implementation Skeleton (FastAPI-first, keeps your current posture)

Even if your backend is Node now, you can implement the assistant service in FastAPI as a separate service and call internal endpoints.

Minimal service components

assistant_service/

routes.py (sessions/run)

context.py (artifact/graph retrieval)

schemas.py (pydantic models)

validator.py (policy enforcement)

engine.py (AI + deterministic fallback)

Deterministic fallback engine

Graph queries: pure DB traversal / API call results

Risk scoring: rules-based (existing risk engine)

PMESII: use stored cards if present; otherwise UNKNOWN
